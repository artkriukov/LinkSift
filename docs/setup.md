# Локальный запуск LinkSift

Проект запускается напрямую на macOS в изолированном Python-окружении `.venv`.
Docker, Redis и отдельный worker на текущем этапе не нужны.

## Что уже подготовлено

- Python 3.12 и зависимости зафиксированы в `uv.lock`;
- `.venv` создан в корне проекта и исключён из Git;
- FastAPI предоставляет liveness endpoint;
- aiogram запускает публичного Telegram-бота через long polling;
- Pydantic валидирует конфигурацию и контракты анализа;
- Supabase PostgreSQL хранит материалы, попытки обработки и результаты;
- Alembic управляет схемой базы данных;
- Ruff, pytest и GitHub Actions проверяют код.

Анализ ссылок и файлов, AI-провайдеры и очистка временных медиа пока не
реализованы. Бот сообщает об этом явно.

## Первый запуск

```sh
cd /Users/artemkriukov/Desktop/LinkSift
cp .env.example .env  # только в свежем клоне; текущий .env уже создан
uv sync --locked
make db-upgrade
```

`uv` нужен только для первоначального создания или обновления `.venv`. Команды
`make` обращаются к `.venv/bin` напрямую, поэтому после подготовки окружения
глобально установленный `uv` им не требуется. Активировать окружение также
необязательно. Для обычного активированного shell: `source .venv/bin/activate`.

## Проверка кода

```sh
make check
make test
```

Ожидаемый результат: Ruff и unit-тесты проходят без ошибок, PostgreSQL integration-
тест пропускается без `LINKSIFT_TEST_DATABASE_URL`.

## Запуск API

```sh
make api
```

После запуска терминал остаётся занят сервером и показывает запросы. В другом
терминале:

```sh
curl --fail http://127.0.0.1:8000/health/live
```

Ожидаемый ответ: `{"status":"ok","service":"linksift-api"}`. Остановка —
`Ctrl+C`. API пока технический каркас; для polling-бота он не обязателен.

## Запуск Telegram-бота

В `.env` заполнить две обязательные переменные:

```dotenv
LINKSIFT_BOT_TOKEN=токен_от_BotFather
LINKSIFT_DATABASE_URL=postgresql+psycopg://...
```

Затем применить миграции командой `make db-upgrade`, выполнить `make bot` и отправить
боту `/start`. Бот доступен любому Telegram-пользователю, но принимает сообщения
только в личном чате. Остановка — `Ctrl+C`. Один токен нельзя одновременно
использовать в двух polling-процессах.

## Конфигурация

Все параметры имеют префикс `LINKSIFT_`; образец находится в `.env.example`.
`.env` и `.venv` не попадают в Git. Бот без token или database URL завершается до
начала polling с безопасной ошибкой конфигурации. Telegram ID пользователь не вводит:
он берётся из `message.from_user.id`.

`LINKSIFT_DATA_DIR` используется только для будущих временных медиа: постоянные
данные хранятся в PostgreSQL. Лимиты по умолчанию: 30 минут, 20 MB, media TTL
1 час и история 30 дней. Они начнут применяться после реализации pipeline.
`ANALYSIS_PIPELINE=gemini|local` задаёт будущий выбор провайдера; адаптеры ещё
не подключены.

## Когда вернуть Docker и очередь

Docker имеет смысл добавить перед развёртыванием на VPS или когда потребуется
повторяемая системная среда с ffmpeg/Whisper/OCR. Redis и отдельный worker нужны,
когда тяжёлая обработка должна переживать перезапуск процесса или выполняться
параллельно. Для текущего личного прототипа достаточно `.venv`, одного процесса
бота и Supabase.

[архитектуру](architecture.md) и [Git workflow](git-workflow.md).
